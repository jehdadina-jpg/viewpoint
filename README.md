# VIEWPOINT

**Sentiment-driven Black-Litterman portfolio optimization.** Sentiment becomes a viewpoint; the viewpoint becomes a Black-Litterman view. In-app function mnemonic: `SBLV <GO>`.

A full-stack research platform that turns financial news sentiment — scored by an
**ensemble of NLP models** — into Black-Litterman views, optimizes a long-only
portfolio around them, walk-forward backtests it against two benchmarks, and
presents everything in a Bloomberg-terminal-style dashboard.

```
news/social text ──► VADER ─┐
                     FinBERT ├─► confidence-weighted ensemble ─► daily score + dispersion
                     LM lexicon ┘        (time-decayed, volume-weighted)
                                                      │
market caps ─► equilibrium prior  π = δΣw ────────────┼──► Black-Litterman posterior μ_BL
                                                      │        (P, Q from z-scores; Ω from dispersion)
                                                      ▼
                                       long-only MV optimizer (≤15%/name, turnover penalty)
                                                      │
                                     monthly walk-forward backtest vs. cap-weight & 1/N
                                        (10bp costs, vol-regime split, no look-ahead)
                                                      │
                                              FastAPI + React terminal UI
```

## 1. Quick start (everything runs locally, no keys required)

Prerequisites: Python 3.11+, Node 18+.

```bash
# --- backend ---
cd backend
python -m pip install -r requirements.txt
python -m pipeline.run          # pulls prices (yfinance), generates/scores news, runs backtest  (~3 min first time)
python -m uvicorn api.main:app --port 8000
```

```bash
# --- frontend (second terminal) ---
cd frontend
npm install
npm run dev                     # http://localhost:5173  (proxies /api and /ws to :8000)
```

The first `pipeline.run` downloads **FinBERT (~440 MB)** from HuggingFace and scores
every headline once; results are cached in `backend/storage/market.db`, so
subsequent runs take seconds. Run the tests with `cd backend && python -m pytest`.

### Swapping in live data (zero code changes)

Edit `backend/config.yaml`:

| Setting | Options | Notes |
|---|---|---|
| `prices.provider` | `yfinance` / `sample` | yfinance needs no key. `sample` = synthetic GBM for offline demos. |
| `news.provider` | `sample` / `newsapi` / `reddit` / `yfinance` | Keys are read from env vars named in the config (`NEWSAPI_KEY`, `REDDIT_CLIENT_ID`, `REDDIT_CLIENT_SECRET`). |
| `universe.tickers` | any list | Default: 16 large-caps across 6 sectors. |
| `sentiment.models.*` | enable / weight | Add a model by implementing `SentimentScorer` (see §3). |

Then `python -m pipeline.run --force`.

**Important honesty note.** No free news API offers a multi-year archive, so the
*historical* headlines used by the backtest are generated by
`backend/data/sample_data.py` and flagged `is_synthetic=1` everywhere (the UI
shows a `SAMPLE` badge). Their tone is tied to the stock's *trailing* 5-day return
plus noise — news reacting to price, never the other way round — so there is no
leakage, but it also means the backtest demonstrates **the machinery**, not a
proven edge. With a live provider configured, recent days use real headlines and
older days stay synthetic; plug in a paid archive (e.g. RavenPack, GDELT, a
Kaggle dump) via a new `NewsProvider` subclass to backtest on real text.

## 2. Academic basis

| **Creamer (2015)**, *Can a corporate network and news sentiment improve portfolio optimization using the Black-Litterman model?* | Pre-LLM precedent: dictionary-based news sentiment has a high-frequency effect on excess returns and is regime-dependent → we keep a Loughran-McDonald dictionary member and report regime-split metrics. | `sentiment/lexicon_scorer.py`, `backtest/engine.py` |

| **Araci (2019)**, *FinBERT* | The financial-domain transformer (`ProsusAI/finbert`). | `sentiment/finbert_scorer.py` |

### 3.1 Sentiment ensemble (the differentiator)

Every headline is scored by each model; each model returns a **score** and its own
**confidence**. The per-headline ensemble score is

```
s_h = Σ_m  w_m · c_hm · s_hm  /  Σ_m  w_m · c_hm
```

where `w_m` is a static model weight (FinBERT 1.5, VADER 1.0, LM 0.5) and `c_hm`
is model *m*'s confidence on *that* headline — a model that shrugs is down-weighted
only where it shrugs. Why three models? On our headline set VADER scores 32% of
finance headlines as exactly 0 ("beats estimates", "regulatory probe" aren't in its
lexicon) — precisely the single-model bias the ensemble fixes. Inter-model
correlations are 0.80–0.93: aligned enough to trust, different enough to matter.

Daily aggregation for stock *i* on trading day *D* uses headlines in
`(D − 10 days, D 21:00 UTC]` with exponential time decay (half-life 3 days):

```
w_h        = exp(−ln2 · age_h / half_life)
score      = Σ w_h s_h / Σ w_h
dispersion = ½ · ( weighted std of s_h  +  weighted mean of std_m(s_hm) )
             ─────── headlines disagree ──   ──── models disagree ────
confidence = (1 − dispersion) · (1 − exp(−N_eff / 3))        N_eff = Σ w_h  (volume weighting)
```

`LearnedCombiner` in `aggregator.py` is the typed extension point for the
paper's LSTM / logistic aggregator (must be trained walk-forward).

### 3.2 Black-Litterman — the math you'll be asked about

**Prior (reverse optimization).** Instead of estimating expected returns, ask
what returns would make a mean-variance investor hold the market portfolio:

```
π = δ Σ w_mkt                        δ = risk aversion (2.5), Σ = annualised shrunk covariance
```

**Views.** K absolute views on individual stocks. `P` (K×N) has a unit row per
viewed stock, `Q` (K) is the view return, `Ω` (K×K, diagonal) is view uncertainty.

**Posterior (the master formula).**

```
μ_BL = [ (τΣ)⁻¹ + Pᵀ Ω⁻¹ P ]⁻¹ · [ (τΣ)⁻¹ π + Pᵀ Ω⁻¹ Q ]
Σ_BL = Σ + [ (τΣ)⁻¹ + Pᵀ Ω⁻¹ P ]⁻¹
```

A precision-weighted blend of the prior and the views. Ω → ∞ recovers π (hold
the market); Ω → 0 imposes the views exactly. `tests/test_black_litterman.py`
checks both limits and that a view on one stock propagates to correlated names.

**How sentiment becomes (P, Q, Ω)** — `optimization/views.py`:

1. **z-score** each stock's ensemble sentiment over a trailing 60-day window
   (using only data ≤ rebalance date). This removes per-name coverage bias.
2. Only stocks with `|z| ≥ 0.5` get a view → fewer, stronger views.
3. **Q via Monte Carlo** (Colasanto et al.): simulate GBM over the 21-day horizon
   with drift `π_i + 0.06·z_i`; `Q_i` = annualised mean simulated return (also
   yields the target price shown in the UI).
4. **Ω from dispersion**: `Ω_ii = τ Σ_ii (1 + 4·d_i) + floor`, `d_i` = normalised
   dispersion. Noisy sentiment ⇒ wide Ω ⇒ optimizer leans on the market prior.
   This is how the ensemble's *uncertainty*, not just its point estimate, reaches
   the portfolio.

**Final weights.**

```
max_w  μ_BLᵀw − (δ/2) wᵀ Σ_BL w − λ‖w − w_prev‖²     s.t. Σw = 1,  0 ≤ w_i ≤ 0.15
```

Solved with SLSQP. The turnover penalty (λ = 2) is what keeps the strategy from
flipping names between 0% and the cap every month (without it turnover was ~8×/yr).

### 3.3 Backtest

* Rebalance on the last trading day of each month `D_k`; weights use only data
  `≤ D_k` (covariance, sentiment, dispersion) and are applied to returns from
  `D_k + 1`. Sentiment for `D_k` only includes headlines up to that day's close.
* Weights drift buy-and-hold inside the month; turnover at `D_{k+1}` is
  `Σ|w_target − w_drifted|`.
* 10 bp per unit of one-way turnover, charged on the first day of the new period.
  Gross and net are both reported; **net is what matters**.
* Three portfolios: **sentiment-tilted BL**, **market-cap** (monthly rebalanced),
  **equal-weight** (monthly rebalanced).
* **Regime split**: 21-day realised vol of the market-cap benchmark, split at its
  median → every day is *high-vol* or *low-vol*; all metrics recomputed per regime.

### 3.4 Look-ahead bias — where it's enforced

Search the code for `NO LOOK-AHEAD`:

| Place | Guard |
|---|---|
| `sample_data.py` | synthetic tone uses `returns.iloc[:i]` only (trailing) |
| `aggregator.py` | headlines ≤ `D 21:00 UTC` for day `D` |
| `views.py::sentiment_zscores` | `sent.loc[:as_of]` before any statistic |
| `engine.py` | `rets.loc[:as_of]`, `sent.loc[:as_of]`, returns applied from `as_of+1` |
| `tests/test_no_lookahead.py` | tampering with future data must not change past signals |

Known limitation: market caps are *current* (yfinance has no history), so the
cap-weighted prior/benchmark carries mild survivorship drift. State this if asked.

## 4. Results (default config, real yfinance prices 2022-01 → 2025-12, synthetic news)

Net of 10 bp costs, 48 monthly rebalances:

| | Sentiment-tilted BL | Market-cap | Equal-weight |
|---|---|---|---|
| Annualised return | 26.1% | 28.4% | 19.5% |
| Sharpe | **0.94** | 0.93 | 0.89 |
| Sortino | 1.40 | 1.38 | 1.30 |
| Max drawdown | **−30.3%** | −34.8% | −20.7% |
| Beta vs cap-weight | 0.88 | 1.00 | 0.60 |
| Annual turnover | 95% | 89% | 89% |

Read this honestly: the BL portfolio matches the cap-weighted benchmark on
risk-adjusted terms with a shallower drawdown, at slightly lower absolute return
(it cannot hold NVDA above 15%; the benchmark held ~20%). Because the news is
synthetic and price-reactive, the tilt behaves like a diversified momentum
overlay — the point of the demo is the pipeline, not the alpha. Regenerate the
table from the UI's *Regime Split* toggle or `GET /portfolio/stats`.

## 7. Metric glossary (for the Q&A)

| Metric | Definition | Why it matters |
|---|---|---|
| **Annualised return** | `(final equity)^(252/n) − 1` | Headline growth rate. |
| **Sharpe** | `mean(r − rf) / std(r − rf) · √252` | Return per unit of total risk. rf = 4%. |
| **Sortino** | `mean(r − rf)·252 / downside deviation` | Like Sharpe but only penalises downside vol. |
| **Max drawdown** | `min(equity / running max − 1)` | Worst peak-to-trough loss — what an investor actually feels. |
| **Calmar** | `annualised return / |max drawdown|` | Return per unit of worst-case pain. |
| **Alpha (ann.)** | intercept of `r_p − rf = α + β(r_b − rf)` | Return not explained by benchmark exposure. |
| **Beta** | slope of the same regression | Sensitivity to the benchmark. |
| **Turnover** | `Σ|Δw|` per rebalance, annualised | Drives transaction costs; >100%/yr is expensive. |
| **Tracking error / IR** | std of `(r_p − r_b)` / mean over std | How different from, and how efficiently different from, the benchmark. |
| **Regime split** | metrics on days with realised vol above/below its median | Sentiment strategies behave differently in stress. |
| **Dispersion** | disagreement across models × headlines | Low-confidence signal → wide Ω → smaller tilt. |

## 8. Extending

* **Learned ensemble** — implement `LearnedCombiner.combine()` (walk-forward LSTM / logistic regression on model scores → forward return sign).
* **Real archive** — subclass `NewsProvider` in `news_fetcher.py`, set `news.provider`.
* **Relative views** — add rows to `P` with `+1/−1` (e.g. "NVDA beats AMD by 3%") in `views.py::build_views`.
* **Historical market caps** — replace `cap_weights()` with a dated cap table to remove the prior's survivorship drift.
* **Another sentiment model** — implement `SentimentScorer` (e.g. an LLM API), register it in `build_scorers()` and `config.yaml`.
